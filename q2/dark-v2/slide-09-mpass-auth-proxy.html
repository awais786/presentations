02
The Incompatibility
The mPass OIDC endpoint is not consumable by standard oauth2-proxy:
  • Hosted login UI instead of a standard /authorize endpoint
  • Tokens returned as query params, no auth code to redeem
  • No state round-trip, so CSRF correlation is lost
  • No PKCE support on the provider side
03
The Translation Layer
We built mpass-auth-proxy, a FastAPI bridge that makes mPass look like a standard OIDC provider:
  • Emulates /authorize + /token, mints one-shot auth codes
  • Enforces PKCE (S256) and state via Redis-backed bridge state
  • Verifies tokens against the real IdP JWKS, gates on corporate identity
  • oauth2-proxy runs unmodified, one flow across every product
In The Open github.com/Pressingly/mpass-auth-proxy - published under GPL-3.0, alongside the public app forks and the foss-sso-e2e test harness.
